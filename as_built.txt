Last updated: 2026-11-18 (v60: sheet append removed)

OVERVIEW
Weekly automation that, for each closed/unresponsive lead in
closed_sequence_threads, finds DIFFERENT people at the same company who hold one of
the target POC roles (names + job titles only — NO emails — via the Apify actor
deepmine~linkedin-company-employees), records them in alternate_leads (email NULL),
and emails Liv a preview of the leads found that run. It NO LONGER appends to the Google
Sheet (removed in edge function v60).
Hunter.io, the older Apify email-finder actor and Lusha are NOT used any more.

EDGE FUNCTION
- supabase/functions/alternate-lead-finder/index.ts — Deno + @supabase/supabase-js
  (service role), verify_jwt=false. Deployed to project aivitcomiywiysrfwqxt
  (currently version 60). URL:
  https://aivitcomiywiysrfwqxt.supabase.co/functions/v1/alternate-lead-finder
  Flow:
  1. Queue: up to 20 rows (MAX_ROWS_PER_RUN, hard cap; ?limit=N can only lower it) from
     closed_sequence_threads where email is not null AND is_processed is null/false AND
     failed_apify_search is NOT true, oldest id first.
  2. Pre-pass (parallel): group rows by email domain -> one company per domain. Resolve
     the company NAME: soc-med context org -> the original lead's org by email
     (loadOrgByEmail over ai_verified_cold_leads / manually_found_cold_leads /
     ai_scraped_soc_med_leads / manually_found_leads) -> OpenAI web-search resolver
     (asks for the common/LinkedIn trading name) -> bare domain. Then ONE DeepMine search
     per company, all in parallel (DEEPMINE_CONCURRENCY=20, maxResults 100,
     enrichProfiles=false). Measured: 18 companies in 78s (~90s per full run).
  3. Per row: pick up to 5 people whose JOB TITLE matches TARGET_ROLE_PATTERNS
     (word-boundary regexes: event(s), conference(s), marketing, communication(s),
     learning & development / L&D, people & culture, executive assistant). No fallback.
     Exclude the unresponsive lead themself (name vs original email) and people already
     in alternate_leads (dedup by name+org and name+email-domain). Insert into
     alternate_leads with email NULL (lead_type 'soc med' for follow_up_sequence_threads
     source, else 'cold'; carry speaker/event/subject for soc med).
  4. Flags on closed_sequence_threads: lead inserted -> is_processed=true,
     failed_apify_search=false. Search ran but no matching lead -> failed_apify_search=true
     (row is then skipped by the queue; set to null to retry). If the company has NO
     target-role people at all, all other unprocessed rows for the same email domain are
     also flagged true (markCompanyFailed). Provider error / no token / cap / wall-clock
     skip -> flag stays null and the row retries.
  5. Notify: email a dynamic HTML preview (up to 100 rows) to Liv of ONLY the leads inserted
     this run (notifyNewLeads; a lead with no email shows "—"; no email if none inserted).
     No sheet writes; is_added_to_sheet is no longer maintained (new rows stay false).
  Runs work in EdgeRuntime.waitUntil, returns 202.
  WALL-CLOCK GUARD: isolate is hard-killed at ~150s; searches only start while
  elapsed < WALL_CLOCK_MS - APPEND_RESERVE_MS - APIFY_CALL_RESERVE_MS; skipped ones retry.
  Debug query params: ?sync=1 (await + return summary), ?limit=N, ?inspect=1 (check
  Sheets/Gmail/AC access, no send), ?append=1 (DISABLED no-op), ?probe=<company or
  domain> (alias ?aprobe=; raw DeepMine search, no writes — shows people returned, target
  matches, picker output), ?orgprobe=<domain> (OpenAI org resolver, optional &hint=),
  ?fixorg=1 (sync sheet Org column to DB by email; skips email-less leads),
  ?to=<email> (override email recipient; ALWAYS use when testing).
  Requires (edge-function secrets, set in Supabase — NOT in the repo):
  SUPABASE_URL, SUPABASE_SERVICE_ROLE_KEY (auto-injected), APIFY_API_TOKEN,
  OPENAI_API_KEY, GOOGLE_SERVICE_ACCOUNT_JSON. (AC_API_URL / AC_API_TOKEN and
  HUNTER_IO_API_KEY are still set but unused by the current flow.) Optional overrides:
  NOTIFY_TO (default liv@myadventuregroup.com.au), NOTIFY_FROM (default
  julienne@myadventuregroup.com.au), SALES_SHEET_ID, ALT_LEADS_TAB, APIFY_ACTOR (default
  deepmine~linkedin-company-employees), DEEPMINE_MAX_RESULTS (100), DEEPMINE_TIMEOUT_S
  (90), DEEPMINE_CONCURRENCY (20), APIFY_MAX_DOMAINS (80), OPENAI_MODEL (default gpt-4o),
  WALL_CLOCK_MS (150000), APPEND_RESERVE_MS (15000), APIFY_CALL_RESERVE_MS (75000).

DATA STORES (project aivitcomiywiysrfwqxt)
- alternate_leads — master record of alternate leads found. Columns = union of
  closed_sequence_threads + follow_up_sequence_threads (deduped) plus lead_type,
  org, event, poc_lastname, poc_role, is_added_to_sheet (no longer maintained), and
  sheet_remark (text, added 2026-11-18: ONE-TIME copy of the sheet's Remark column —
  "Send intro" 44 / "5A" 30 / null 70 — matched by email; not kept in sync).
  email is NULLABLE and is NULL for DeepMine leads. Own bigserial PK, RLS on. 144 rows.
- closed_sequence_threads — input; source_table in {cold_leads_follow_up_sequence_
  threads, follow_up_sequence_threads, bounced}. Flags: is_processed (true once a lead was
  inserted) and failed_apify_search boolean (added 2026-11-18: true = search ran, no
  matching lead; false = processed with a matching lead; null = not searched / provider
  error). As of the 2026-11-18 test runs: 24 processed ok, 39 flagged failed, ~200 pending.
- follow_up_sequence_threads, cold_leads_follow_up_sequence_threads,
  ai_scraped_soc_med_leads, ai_verified_cold_leads, manually_found_cold_leads,
  manually_found_leads — read to carry speaker/event/context and the original lead's org.
- activecampaign_contacts (~15k) — no longer used for dedup (leads have no email).
